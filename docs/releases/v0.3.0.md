# cc: v0.3.0

Local release candidate. This version has not been published.

## Changes

- Rename the visible product and app bundle to `cc:` and `cc.app`, with the new
  icon. The bundle identifier, local data directory, `context` command, and
  existing release URLs remain compatible.
- Use the Menu Bar shelf by default, with an optional Notch shelf. Both share
  the same saved files, links, and notes.
- Add Settings for appearance, shelf presentation, keyboard shortcuts, and
  updates. Explicit update-check preferences survive development app restarts.
- Include the `context` CLI and optional `context-handoff` skill installer for
  exchanging local shelf items with agents. Skill installation remains opt-in.
- Keep saved file copies when exporting them, and remove unused move and import
  helpers. Make shell syntax errors fail the repository checks immediately.

## Distribution

- Requires macOS 26 or later; the release package targets Apple Silicon and Intel.
- The DMG and ZIP contain `cc.app`, its CLI, and Sparkle.
- The existing installer accepts both the former `Context.app` and `cc.app` and
  preserves a migration backup when replacing the former bundle.
- Update archives use the existing Sparkle Ed25519 signing key and feed URL.
- This candidate uses ad-hoc app signing and is not notarized by Apple. A valid
  bundle signature does not imply Developer ID signing or notarization.

The public release remains v0.2.3 until this candidate is published. Preparing
the candidate does not install it, change the public appcast, or deploy the site.

## Preparation

Run `make check`, then `make package VERSION=v0.3.0`. The existing packaging
script creates `dist/context-macos.zip`, `dist/context-macos.dmg`, and, when the
existing signing key is available, `dist/appcast.xml`.

Before publication, verify the ZIP and DMG, both CPU architectures, the bundled
CLI and optional skill installer, the appcast signature against the embedded
public key, and a local installer migration using isolated test data. Keep the
source commit, checksums, and validation results with the prepared artifacts.

Publishing the version tag runs the GitHub release workflow. Do that only when
publication is explicitly requested. Update the site's displayed version when
the new public release is available.
